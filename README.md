# HIKARI 制作ハブ

HIKARI エンジンでゲームを作るチームのための作業台。作品ごとに claude.ai のページ（ハブ）があり、ルール・エンジン知識・調整ガイド・報告・不具合・質問・ナレッジ・ミス帳を、人と全員のエージェントが同じ場所で読み書きする。

考え方：

- **やることは各自が決める。** オーナーが仕事を割り振るわけではない。
- **ルールはオーナーが決める。** ハブのページで書き換えると、全員のエージェントが次の作業から従う。
- **エージェントは必ず跡を残す。** 何をやったか、どこを人が調整できるか、何を間違えたか、何を見つけたか。

このリポジトリには次のものが入っている。

- `plugin/`：Claude Code のプラグイン（スキル `hub:work`、コマンド `/hub:…`、見張りのフック）。ハブのページの雛形と初期データも含む
- `schema/schema.json`：ハブの記録の項目の宣言（ページもエージェント向けの資料もここから作る）
- `content/`：既定のルールとエンジンの必須知識（新しいプロジェクトに入る初期データ）
- `page/`、`tools/`：ページの元と、ビルド

## 参加の手順（メンバー）

ゲームのリポジトリには何もコミットされない。必要なのはプラグインと、手元での「参加」だけ。

1. オーナーから届いた招待メールのリンクを開き、Claude のアカウントでログインする。ハブのページが開く。
2. ページの「メンバー」で、自分の**呼び名**（半角英数字）を登録する。
3. Claude Code（ページと同じ Claude のアカウントでログイン）に、このプラグインを入れる（1 回だけ）：

   ```
   /plugin marketplace add <このリポジトリの owner/name>
   /plugin install hub@hikari-hub
   ```

4. ゲームのリポジトリの中で、参加する（リポジトリごとに 1 回。URL はページの「メンバー」に書いてある）：

   ```
   /hub:join <ハブのページの URL>
   ```

あとは普段どおりエージェントに頼むだけ。そのリポジトリで会話を始めると、エージェントは自動でハブの手順に入る。

**手順 3 と 4 はエージェントに任せてもよい。** ハブのページの「メンバー」にある「エージェントに頼む文」をコピーして、ゲームのリポジトリで開いた Claude Code に貼る。エージェントが `claude plugin marketplace add …` と `claude plugin install hub@hikari-hub` を実行し（確認が出たら許可する）、参加の設定まで行う。終わったら Claude Code を開き直す。

スキルを新しくするとき：`claude plugin marketplace update hikari-hub` のあと `claude plugin update hub@hikari-hub`（またはエージェントに「ハブのスキルを更新して」と頼む）。

## エージェントがすること

| いつ | 何をするか |
|---|---|
| 会話の最初 | このリポジトリがハブに参加していること、登録している作業、守る手順が自動で伝わる |
| 作業の前 | やることをハブに登録する（承認は要らない）。ルール、同じ領域の調整ガイド・ナレッジ・ミス帳を読む |
| 作業中 | 進捗を書く。見つけた問題は不具合に、分からないことは質問板に |
| 作業の終わり | 終了報告、**調整ガイド**（エディタで調整できる値・コードで微調整するところ・確かめ方）、ミス、学んだこと |

| コマンド | すること |
|---|---|
| `/hub:today` | 自分の作業、確認待ち、答えられる質問を見る |
| `/hub:start [やること]` | やることを登録し、ブランチを切り、関係する知識を読んで始める |
| `/hub:progress` | 進捗を 1〜2 行で記録する |
| `/hub:end` | 確かめる・コミット・調整ガイド・終了報告・ミスと学びの記録 |
| `/hub:ask <質問>` | まずハブで探し、なければ質問板に出す |
| `/hub:bug <起きたこと>` | 見つけた問題を登録する（エンジン側はエンジンへの要望へ） |
| `/hub:review [PR]` | ルールとミス帳に照らしてレビューする |
| `/hub:plan <目標>` | 目標をカードに分ける |

人はページで同じことができる：カードを作る、不具合や質問を書く、答える、決める、日報を書く、調整ガイドを読む。

## 道から外れないための仕組み

プラグインのフックは、ハブに参加したリポジトリでだけ働く。

| 仕組み | 何をするか |
|---|---|
| 登録なしでは変更できない | やることをハブに登録するまで、エージェントはファイルを変更できない |
| 元ブランチでは変更できない | 作業のブランチに切り替えるまで止める |
| 保護するパス | オーナーがページで決めたファイル（設定、ビルドなど）を変えるときは、人に確認が出る |
| 報告の不足 | 終了報告に書かれていない項目（調整できるところ、ミスなど）があると、ページに「不足」と出る |

「登録なしでは変更できない」はページのプロジェクト設定でオフにできる。保護するパスもそこで編集する。フックが止めるのはエージェントの編集ツールで、人の作業は止めない。

## オーナーがすること

- **新しいプロジェクト**：ゲームのリポジトリの直下で `/hub:new <作品名>`。ページの公開と、初期のルール・エンジン知識の投入まで行う。
- **招待**：ページの共有メニューから、メールで**編集者**として招待する。「リンクを知っている全員」にはしない（外部の編集者が書けなくなる）。見るだけの人は閲覧者で招待する。
- **ルール**：ページの「ルール」で直接書き換える。メンバーとエージェントは「ルール提案」を出せる。
- **エンジン知識**：ページの「エンジン知識」で直す。プラグインを更新したあと `/hub:upgrade` で、新しい既定の内容を選んで取り込める。
- **SDK を更新したとき**：ページのプロジェクト設定で「HIKARI SDK のバージョン」を直す。版の印が付いたエンジン知識（API の名前やコード例の控え）は、版が合わなくなると「古いかもしれない」と出る。エージェントは控えよりも入っている SDK のヘッダを優先し、食い違いを「エンジンへの要望」に「知識の訂正」として出すので、それを見て直す。
- **おすすめの順番・締切**：ページの「ボード」で、先にやってほしいカードを「予定」に入れられる（強制ではない）。
- **控え**：`/hub:backup`。編集者は技術的には記録を消せるので、定期的に取る。

設定・計画・ルール・エンジン知識は、オーナーだけが書ける（データベースの規則で止まる）。それ以外の記録は編集者全員が書ける。

## 開発（このリポジトリを直す人）

```bash
python -I -X utf8 tools/build.py
```

- `schema/schema.json` か `content/` か `page/hub.src.html` を変えたら必ずビルドして、生成物（`plugin/owner/`、`plugin/skills/work/references/data-model.md`・`engine.md`）も一緒にコミットする。
- `dist/preview-owner.html` と `dist/preview-member.html` は、見本データで動く手元の確認用（`python -m http.server --directory dist` で開く）。
- フック（`plugin/hooks/hub-hook.ps1`）は ASCII だけで書く。文言は `hub-messages.json` に置く。
- コミットメッセージは `<種別>(<範囲>): <日本語> / <中文>`。
