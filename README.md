# HIKARI 制作ハブ

HIKARI エンジンでゲームを作るチームのための作業台。チームのサイト（ハブ）に作品ごとのデータベースがあり、ルール・エンジン知識・調整ガイド・報告・不具合・質問・ナレッジ・ミス帳を、人と全員のエージェントが同じ場所で読み書きする。

- サイト：https://hikari39764-cell.github.io/HIKARI_HUB_SKILL/ （Google アカウントでログイン。オーナーに招待された人だけが作品を開ける）

考え方：

- **やることは各自が決める。** オーナーが仕事を割り振るわけではない。
- **ルールはオーナーが決める。** ハブのページで書き換えると、全員のエージェントが次の作業から従う。
- **エージェントは必ず跡を残す。** 何をやったか、どこを人が調整できるか、何を間違えたか、何を見つけたか。

このリポジトリには次のものが入っている。

- `plugin/`：Claude Code のプラグイン（スキル `hub:work`、コマンド `/hub:…`、見張りのフック、ハブを読み書きする `hub` コマンド）
- `docs/`：ハブのサイト（GitHub Pages が配る。ビルドの生成物）
- `schema/schema.json`：ハブの記録の項目の宣言（サイトもエージェント向けの資料もここから作る）
- `content/`：既定のルールとエンジンの必須知識（新しい作品に入る初期データ）
- `page/`、`tools/`：サイトの元と、ビルド

## 参加の手順（メンバー）

ゲームのリポジトリには何もコミットされない。

1. 自分の Google アカウントのメールをオーナーに伝えて、作品に招待してもらう。サイトを開いて、そのアカウントでログインする。
2. 自分の Claude Code に、このスキルを入れてもらう。エージェントにこう頼む：

   ```
   このスキルを入れてください：https://github.com/hikari39764-cell/HIKARI_HUB_SKILL
   ```

   エージェントが `claude plugin marketplace add hikari39764-cell/HIKARI_HUB_SKILL` と `claude plugin install hub@hikari-hub` を実行する（確認が出たら許可する）。終わったら Claude Code を開き直す。自分で入れるなら、Claude Code で `/plugin marketplace add hikari39764-cell/HIKARI_HUB_SKILL` と `/plugin install hub@hikari-hub`。
3. サイトの「メンバー」で **「鍵をコピー」** を押し、エージェントに「ハブにつないで」と言う（パソコンごとに 1 回）。

あとは普段どおりエージェントに頼むだけ。ハブのプロジェクトになっているリポジトリで会話を始めると、エージェントは自動でハブの手順に入る（どのリポジトリがどの作品かは、スキルの中の `projects.json` が `origin` の `owner/name` で見分ける）。

スキルを新しくするとき：`claude plugin marketplace update hikari-hub` のあと `claude plugin update hub@hikari-hub`（またはエージェントに「ハブのスキルを更新して」と頼む）。

### 鍵について

- 鍵は、ログインしたあなた本人としてハブを読み書きするためのもの。エージェントの `hub` コマンドが、これを使ってあなたの名前で読み書きする。できることは、あなたがサイトでできることと同じ（ルールを書き換えられるのはオーナーだけ）。
- 「鍵をコピー」でクリップボードに入り、エージェントの `hub login` がそこから読む。このパソコンの Windows ユーザーだけが使える形で `%USERPROFILE%\.hikari-hub\key.json` に保存され、リポジトリには入らない。
- 人に渡さない・チャットに貼らない。漏れたかもしれないときはオーナーに伝える（招待から外せば、その鍵では読み書きできなくなる）。

## エージェントがすること

| いつ | 何をするか |
|---|---|
| 会話の最初 | このリポジトリがハブに参加していること、登録している作業、守る手順が自動で伝わる |
| 作業の前 | やることをハブに登録する（承認は要らない）。ルール、同じ領域の調整ガイド・ナレッジ・ミス帳を読む |
| 作業中 | 進捗を書く。見つけた問題は不具合に、分からないことは質問板に |
| 作業の終わり | 終了報告、**調整ガイド**（エディタで調整できる値・コードで微調整するところ・確かめ方）、ミス、学んだこと |

| コマンド | すること |
|---|---|
| `/hub:login` | ページでコピーした鍵を受け取って、ハブにつなぐ（パソコンごとに 1 回） |
| `/hub:today` | 自分の作業、確認待ち、答えられる質問を見る |
| `/hub:start [やること]` | やることを登録し、ブランチを切り、関係する知識を読んで始める |
| `/hub:progress` | 進捗を 1〜2 行で記録する |
| `/hub:end` | 確かめる・コミット・調整ガイド・終了報告・ミスと学びの記録 |
| `/hub:ask <質問>` | まずハブで探し、なければ質問板に出す |
| `/hub:bug <起きたこと>` | 見つけた問題を登録する（エンジン側はエンジンへの要望へ） |
| `/hub:review [PR]` | ルールとミス帳に照らしてレビューする |
| `/hub:plan <目標>` | 目標をカードに分ける |

人はサイトで同じことができる：カードを作る、不具合や質問を書く、答える、決める、日報を書く、調整ガイドを読む。

## 道から外れないための仕組み

プラグインのフックは、ハブのプロジェクトのリポジトリ（`plugin/projects.json` に載っているもの）でだけ働く。

| 仕組み | 何をするか |
|---|---|
| 登録なしでは変更できない | やることをハブに登録するまで、エージェントはファイルを変更できない |
| 元ブランチでは変更できない | 作業のブランチに切り替えるまで止める |
| 保護するパス | オーナーがページで決めたファイル（設定、ビルドなど）を変えるときは、人に確認が出る |
| 報告の不足 | 終了報告に書かれていない項目（調整できるところ、ミスなど）があると、ページに「不足」と出る |

「登録なしでは変更できない」はページのプロジェクト設定でオフにできる。保護するパスもそこで編集する。フックが止めるのはエージェントの編集ツールで、人の作業は止めない。

## オーナーがすること

- **新しい作品**：ゲームのリポジトリの直下で `/hub:new <作品名>`。`plugin/projects.json` への登録、初期のルール・エンジン知識の投入まで行う。
- **招待**：作品のページの「メンバー」→「招待する」に、メンバーの **Google アカウントのメール**を足す。外すと、その人とそのエージェントは読み書きできなくなる。招待の一覧はオーナーにしか見えない。
- **ルール**：ページの「ルール」で直接書き換える。メンバーとエージェントは「ルール提案」を出せる。
- **エンジン知識**：ページの「エンジン知識」で直す。スキルを更新したあと `/hub:upgrade` で、新しい既定の内容を選んで取り込める。
- **SDK を更新したとき**：ページを直す必要はない。エンジン知識は考え方と進め方だけで、API と版はエージェントが入っている SDK のヘッダを自分で読む。知識やコード例が実際と食い違っていたら、エージェントが「エンジンへの要望」に「知識の訂正」として出すので、それを見て直す。
- **おすすめの順番・締切**：ページの「ボード」で、先にやってほしいカードを「予定」に入れられる（強制ではない）。
- **控え**：`/hub:backup`。

だれが何をできるかは、データベースの規則で決まる（サイトの画面やエージェントを書き換えても越えられない）。

| | 読む | 記録を作る・直す | 設定・ルール・エンジン知識を書く、招待、削除 |
|---|---|---|---|
| オーナー（規則に書いたメールの Google アカウント） | ○ | ○ | ○ |
| メンバー（その作品に招待された人と、そのエージェント） | ○ | ○ | × |
| それ以外 | × | × | × |

## ハブを置いている場所（オーナー向け）

- データベースとログインは Firebase（Firestore と Google ログイン、無料枠）。接続先は `plugin/hub.json`。ここにある `apiKey` は接続先を示す公開の識別子で、秘密ではない（守っているのはデータベースの規則）。
- 規則は `python -I -X utf8 tools/build.py` が `firebase/firestore.rules` に作る（コミットしない）。オーナーのメールは `firebase/owner-email.local`（1 行。これもコミットしない）から入る。Firebase コンソールの Firestore Database →「ルール」に貼って公開する。
- サイトは `docs/`。GitHub のリポジトリ設定 → Pages で「Deploy from a branch」「main」「/docs」を選ぶ。Firebase コンソールの Authentication → 設定 →「承認済みドメイン」に `hikari39764-cell.github.io` を足す。
- 無料枠の目安：読み取り 1 日 5 万件・書き込み 1 日 2 万件。画像はファイル置き場が無いので、縮めてデータベースに入れている（1 枚 約 0.9 MB まで。動画は入らない）。

## 開発（このリポジトリを直す人）

```bash
python -I -X utf8 tools/build.py
```

- `schema/schema.json`・`content/`・`page/hub.src.html`・`plugin/hub.json`・`plugin/projects.json` を変えたら必ずビルドして、生成物（`docs/`、`plugin/owner/seed/`、`plugin/lib/collections.json`、`plugin/skills/work/references/data-model.md`・`engine.md`）も一緒にコミットする。
- `dist/preview-owner.html` と `dist/preview-member.html` は、見本データで動く手元の確認用（`python -m http.server --directory dist` で開き、`?p=sample` を付ける。`?out=1` でログイン前の画面）。
- PowerShell のスクリプト（`plugin/hooks/hub-hook.ps1`、`plugin/tools/hub.ps1`、`plugin/lib/hub-common.ps1`）は ASCII だけで書く。フックの文言は `hub-messages.json` に置く。
- コミットメッセージは `<種別>(<範囲>): <日本語> / <中文>`。
