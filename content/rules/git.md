## ブランチとマージ

- ブランチは 3 段：作業ブランチ → **`develop`**（元ブランチ。みんなの作業を集める）→ **`main`**（公開ブランチ。いつでも遊べる・提出できる状態）。
- 作業ブランチは最新の `develop` から切る：`<種別>/<カード id>-<英語の短い名前>`（例 `feat/c-k3j9a-enemy-knockback`）。1 カード 1 ブランチ。
- PR は `develop` に向ける。作業ブランチから `main` へ直接は取り込まない。`main` は `develop` からだけ取り込む。
- **`develop` へのマージも、そのたびに人に確かめる**：「<ブランチ> を develop にマージしてよいか」を聞き、はっきり「はい」と言われてからマージする。レビューの承認だけではマージしない。前に言われた「はい」は次のマージに使わない。作業ブランチ → `develop` は squash。マージしたブランチは消す。
- **`main` へのマージは、人が「main にマージ」と明言したときだけ**。「マージして」「取り込んで」だけなら `develop` のこと。`main` への PR やマージを自分から始めない。`develop` → `main` は通常のマージ（squash しない。`develop` と履歴をそろえる）。
- `develop`・`main` に直接 commit・push しない。force push、他人のブランチの書き換えはしない。

## コミットメッセージ

```
<種別>(<範囲>): <何をしたか・日本語 50 字以内>

<なぜ・どう確かめたか（任意）>

Card: <カード id>
```

- 種別：`feat` 新しい機能／`fix` 不具合の修正／`tune` 数値・見た目の調整／`asset` 素材／`level` シーン・レベル／`refactor` 動きを変えない整理／`perf` 速さ／`docs` 文書／`chore` 設定・ビルド
- 例：`fix(プレイヤー): 壁際で被弾すると床に埋まる問題を直す`
- 作業した人の git の名前でコミットする。AI の共同作者行は付けない（どのエージェントが作業したかはハブの報告に残る）。
- 関係ない変更を混ぜない。API キーやパスワードをコミットしない。

## PR と素材

- PR のタイトルはコミットの 1 行目と同じ。本文は終了報告から埋める（結論・変更・確認したこと・未確認）。見た目が変わるときはスクリーンショットを付ける。
- 画像・モデル・音・動画は Git LFS。PSD や Blend のように結合できないファイルは LFS のロックを取ってから編集する。
- `Library/`、ビルド結果、`CMakeUserPresets.json`、個人の設定はコミットしない。
- タグ：`playtest-01`（試遊会）、`submit-20261201`（提出）、`v0.1.0`（公開版）。
