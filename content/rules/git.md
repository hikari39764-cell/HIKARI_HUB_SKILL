## ブランチとマージ

- ブランチは 4 段：作業ブランチ → **自分のブランチ**（メンバーそれぞれの develop。例 `develop_kou`。ハブのメンバー情報に書いてある）→ **`develop`**（元ブランチ。みんなの作業を集める）→ **`main`**（公開ブランチ。いつでも遊べる・提出できる状態）。
- 作業ブランチは最新の自分のブランチから切る：`<種別>/<カード id>-<英語の短い名前>`（例 `feat/c-3fa9c1-enemy-knockback`）。カード id はハブのカードのもの（`c-` と 16 進 6 文字）、英語の名前は半角の小文字・数字・`-` だけ。1 カード 1 ブランチ。
- **作業ブランチ → 自分のブランチ**は本人が入れる（人に確かめなくてよい）。squash でマージし、作業ブランチは消す。自分のブランチは、ときどき `develop` を取り込んで追いつかせる（通常のマージ）。
- **自分のブランチ → `develop` はオーナーだけ**。オーナーでも、そのたびに「<ブランチ> を develop にマージしてよいか」を聞き、はっきり「はい」と言われてからマージする。レビューの承認だけではマージしない。前に言われた「はい」は次のマージに使わない。通常のマージ（squash しない。そのブランチの続きをまた取り込めるように）。
- **`main` へのマージはオーナーだけ、人が「main にマージ」と明言したときだけ**。「マージして」「取り込んで」だけなら `develop` のこと。`main` への PR やマージを自分から始めない。`develop` → `main` は通常のマージ（squash しない。`develop` と履歴をそろえる）。
- PR を使うときは、自分のブランチに向ける。`develop`・`main` へ直接 PR を作らない。
- `develop`・`main`・自分のブランチに直接 commit しない（作業ブランチからだけ入れる）。ほかの人の自分のブランチにはマージも push もしない。force push はしない。

## コミットメッセージ

```
<種別>(<範囲>): <何をしたか・日本語 50 字以内>

<なぜ・どう確かめたか（任意）>

Card: <カード id>
```

- 種別：`feat` 新しい機能／`fix` 不具合の修正／`tune` 数値・見た目の調整／`asset` 素材／`level` シーン・レベル／`refactor` 動きを変えない整理／`perf` 速さ／`docs` 文書／`chore` 設定・ビルド
- 例：`fix(プレイヤー): 壁際で被弾すると床に埋まる問題を直す`
- 1 行目の ( ) と「: 」は半角。2 行目は空行。要約は日本語で、中国語の字・言葉（镜头・节奏・引擎など）を混ぜない。訳を付けるなら 1 行目の後ろに ` / <訳>`、本文は訳の段落の頭に `ZH:` を書く。
- squash で自分のブランチに取り込むときのコミットも同じ形にする（`Card:` も付ける）。
- 作業した人の git の名前でコミットする。AI の共同作者行は付けない（どのエージェントが作業したかはハブの報告に残る）。
- 関係ない変更を混ぜない。API キーやパスワードをコミットしない。
- この形はコミットのたびに git のフックが確かめ、合わないコミットは止まる（ハブのスキルが入れる。種別と字数はこのルールから読む）。エージェントは `--no-verify` などで飛ばさない。

## PR と素材

- PR のタイトルはコミットの 1 行目と同じ。本文は終了報告から埋める（結論・変更・確認したこと・未確認）。見た目が変わるときはスクリーンショットを付ける。
- 画像・モデル・音・動画は Git LFS。PSD や Blend のように結合できないファイルは LFS のロックを取ってから編集する。
- `Library/`、ビルド結果、`CMakeUserPresets.json`、個人の設定はコミットしない。
- タグ：`playtest-01`（試遊会）、`submit-20261201`（提出）、`v0.1.0`（公開版）。
